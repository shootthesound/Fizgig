# Fizgig v9.7.7: repeats from folder names, and several captions per picture

**Repeats from folder names.** With **Also train on its sub-folders** ticked on the Training tab, a new tick, **Repeats from folder names**, reads a number at the start of a sub-folder's name as how many times its pictures are seen each epoch: `10_Laffey_base` ten times, `2_Laffey_casual` twice, a folder without a number once. It's the naming kohya's sd-scripts and OneTrainer use, so a dataset made for them trains here as it is, with any number of folders. A table under the tick shows each folder's pictures, repeats and share of the epoch, so a typo stands out, and suggests the Max Epochs that keeps the run about the same length. If your folder names already look like repeat counts, the sub-folder tick says so and offers to turn both on. It's off by default, and with it off nothing changes (#300, thanks @CrypticCherry, and @tsk5cb-cmyk for the detail).

**Several captions per picture.** A caption file can now hold several captions, one per line, as OneTrainer's do: a line of booru tags and a sentence, or captions from different captioners. Tick **Several captions per picture** on the Training tab and each time a picture trains, one of its lines is picked at random. The tick only shows when your caption files have more than one line; unticked, each file trains as one caption, as before. Put the style you prompt with most on line 1: auto-recaption rewrites only line 1, and training maps and Leave the rest of the model alone use it. Preparing the captions takes longer in proportion to the extra lines; training speed doesn't change (#300, thanks @CrypticCherry and @prookyon).

**Captions a line at a time.** On the Captions tab each line of a caption shows in its own box, every other line shaded like the Samples tab's prompts, and a long caption scrolls in its box. **Add as another line** keeps each file's caption and adds the model's caption on a new line, so captioning twice (say with the WD tagger, then a sentence captioner) builds two-line files. **Add to every line**, in Find, Replace & Add, puts the words on every line instead of at the start and end of the caption.

**Resume at a new size with Enable Cache unticked.** Resume's **At the new size** cached nothing when Enable Cache was off, so the run stopped with "No training items". It now caches at the new size whatever the tick says, and a resume stopped while caching tries again next time instead of failing the same way (#370, thanks @spaghettified26).

**Helper previews for MiniMax H3 on 16 GB cards.** A helper on a 16 GB card loaded H3's int8 base with nothing streamed, ran out of memory and tried again forever, so no previews arrived. It now asks H3's own planner for that card (int8 with blocks streamed) and caps previews at 768×640 and 22 frames, as training does on a 16 GB card. In our test on a helper capped to 16 GB, every epoch's previews arrived, at about 16 s each (#372, thanks @Nessa2026691).
